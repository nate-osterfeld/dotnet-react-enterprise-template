# Reference Guide: Setting up the Test (Staging) and Prod Environments

## Part 1: Prerequisite: Provisioning Your Azure SQL Databases

Before spinning up your test and prod pipelines, you will need to provision distinct Azure Resource Groups for your application environments (e.g., `rg-dotnet-react-test`, and `rg-dotnet-react-prod`), as well as creating their corresponding databases ( `dotnet-react-test`, and `dotnet-react-prod`) under the shared resource group (e.g., `rg-dotnet-react-shared`) to house your Azure SQL Logical Server and its isolated environment databases so that your infrastructure and connection strings have a live target.

- _Note:_ You should ensure your database firewall rules allow Azure services and your IP to connect, and keep your connection strings ready for the next step.

## Part 2: Resource Groups & Database Provisioning

To cleanly separate environments, you will use distinct resource groups while hosting your isolated databases on your **existing Azure SQL Logical Server**.

1. **Create Environment Resource Groups:**

    - Create resource groups for each stage (e.g., `rg-dotnet-react-test` and `rg-dotnet-react-prod`).
    
2. **Populate `appsettings.secrets.json`:**
    
    Ensure your local configuration targets the correct connection strings for your target environment keys:    

```json
{
	"connectionstrings": {
        "_msg": "add any necessary connection string names here, put the strings themselves in appsettings.secrets.json",
        "dotnet-react-db": "Server=tcp:azure-sql-free-1.database.windows.net,1433;Initial Catalog=dotnet-react-dev;Persist Security Info=False;User ID=osterfnl;Password=DB_PASSWORD;MultipleActiveResultSets=False;Encrypt=True;TrustServerCertificate=False;Connection Timeout=30;",
        "dotnet-react-db.dev": "Server=tcp:azure-sql-free-1.database.windows.net,1433;Initial Catalog=dotnet-react-dev;Persist Security Info=False;User ID=osterfnl;Password=DB_PASSWORD;MultipleActiveResultSets=False;Encrypt=True;TrustServerCertificate=False;Connection Timeout=30;",
        "dotnet-react-db.test": "Server=tcp:azure-sql-free-1.database.windows.net,1433;Initial Catalog=dotnet-react-test;Persist Security Info=False;User ID=osterfnl;Password=DB_PASSWORD;MultipleActiveResultSets=False;Encrypt=True;TrustServerCertificate=False;Connection Timeout=30;",
        "dotnet-react-db.prod": "Server=tcp:azure-sql-free-1.database.windows.net,1433;Initial Catalog=dotnet-react-prod;Persist Security Info=False;User ID=osterfnl;Password=DB_PASSWORD;MultipleActiveResultSets=False;Encrypt=True;TrustServerCertificate=False;Connection Timeout=30;"
	}
}
```

3. **Execute Migrations:**
    
    Temporarily point your local application configuration to each of your target databases by removing the ".environment" and run the update command:
    
```bash
dotnet ef database update --project CapstoneApp.Integrations
```

## Part 3: Generating Service Principals & Setting Secrets

Run these commands in your Azure Cloud Shell (`>_` in Bash) replacing `YOUR_SUBSCRIPTION_ID`:

### 1. Test Environment

```bash
az ad sp create-for-rbac --name "dotnet-react-github-actions-test-sp" --role Contributor --scopes /subscriptions/YOUR_SUBSCRIPTION_ID --json-auth
```

**GitHub Secrets Required:**

    - `AZURE_CREDENTIALS_TEST` (JSON output)        
    - `AZURE_SQL_CONNECTION_STRING_TEST`

### 2. Production Environment

```bash
az ad sp create-for-rbac --name "dotnet-react-github-actions-prod-sp" --role Contributor --scopes /subscriptions/YOUR_SUBSCRIPTION_ID --json-auth
```

**GitHub Secrets Required:**

    - `AZURE_CREDENTIALS_PROD` (JSON output)        
    - `AZURE_SQL_CONNECTION_STRING_PROD`

### 3. Shared Registry Secret

- **`ACR_PASSWORD`**: The admin password retrieved from your ACR (`dotnetreactacr`) **Access keys** menu (with Admin user enabled) can stay the same. We do not need any extra configuration here.

## Part 4: GitHub Actions Workflow Files

### 1. Test Pipeline (`.github/workflows/deploy-test.yml`)

**Trigger:** Runs **only when pushing to `main`**.

```yaml
name: Deploy Test Environment

on:
  push:
    branches:
      - staging

jobs:
  build-and-deploy:
    runs-on: ubuntu-latest
    steps:
      - name: Checkout repository
        uses: actions/checkout@v4

      - name: Azure Login
        uses: azure/login@v2
        with:
          creds: ${{ secrets.AZURE_CREDENTIALS_TEST }}

      - name: Create appsettings.secrets File
        run: |
          echo "{
            \"connectionstrings\": {
              \"_msg\": \"add any necessary connection string names here, put the strings themselves in appsettings.secrets.json\",
              \"dotnet-react-db\": \"${{ secrets.AZURE_SQL_CONNECTION_STRING_TEST }}\",
              \"dotnet-react-db.test\": \"${{ secrets.AZURE_SQL_CONNECTION_STRING_TEST }}\"
            }
          }" > CapstoneApp.Host/appsettings.secrets.json

      - name: Log in to ACR via Azure CLI
        run: |
          az acr login --name dotnetreactacr

      - name: Build and push Docker image
        uses: docker/build-push-action@v5
        with:
          context: .
          file: ./Dockerfile
          push: true
          tags: dotnetreactacr.azurecr.io/dotnet-react-app:${{ github.sha }}

      - name: Deploy to Azure Container App
        uses: azure/container-apps-deploy-action@v2
        with:
          containerAppName: dotnet-react-test
          resourceGroup: rg-dotnet-react-shared
          imageToDeploy: dotnetreactacr.azurecr.io/dotnet-react-app:dev-${{ github.sha }}
          acrName: dotnetreactacr
          acrUsername: dotnetreactacr
          acrPassword: ${{ secrets.ACR_PASSWORD }}
          containerAppEnvironment: ${{ vars.CONTAINER_APP_ENVIRONMENT }}
```

## How to Cut a Release for Production:

When you are ready to ship code to production:

1. Go to your GitHub repository homepage.
2. Click on **Releases** (on the right sidebar) $\rightarrow$ **Draft a new release**.
3. Create a new tag (e.g., `v1.0.0`), give your release a title, and click **Publish release**.
4. GitHub Actions will automatically catch that publication event, build your application with your production database secrets, and push a secure release straight to your `dotnet-react-prod` container app!
