# Reference Guide: Configuring `appsettings.secrets.json` & Local Database Connection

### 1. Purpose of `appsettings.secrets.json`

To connect a local application to a database securely, credentials and connection strings are separated from code files. We use an explicit JSON structure containing specific connection string keys targeting our development environments (`dotnet-react-db` and `dotnet-react-db.dev`), leaving room to add `.test` and `.prod` strings later.

### 2. Step-by-Step Implementation Guide

#### **Step A: Create and Populate `appsettings.secrets.json`**

1. In your **`CapstoneApp.Host`** directory, create a new file named **`appsettings.secrets.json`**.
2. Structure the file with your specific database keys, replacing the server and credentials with your actual Azure SQL server details:
```json
{
	"connectionstrings": {
	    "_msg": "add any necessary connection string names here, put the strings themselves in appsettings.secrets.json",
        "dotnet-react-db": "Server=tcp:azure-sql-free-1.database.windows.net,1433;Initial Catalog=dotnet-react-dev;Persist Security Info=False;User ID=osterfnl;Password=DB_PASSWORD;MultipleActiveResultSets=False;Encrypt=True;TrustServerCertificate=False;Connection Timeout=30;",
        "dotnet-react-db.dev": "Server=tcp:azure-sql-free-1.database.windows.net,1433;Initial Catalog=dotnet-react-dev;Persist Security Info=False;User ID=osterfnl;Password=DB_PASSWORD;MultipleActiveResultSets=False;Encrypt=True;TrustServerCertificate=False;Connection Timeout=30;"
	}
}
```

#### **Step B: Load the Secrets File and Update DbContext in `Program.cs`**

1. In your `Program.cs`, ensure your configuration builder loads the secrets file optionally:

```c#
builder.Configuration.AddJsonFile("appsettings.secrets.json", optional: true, reloadOnChange: true);
```

2. When registering your database context, update the connection string name reference from `"DefaultConnection"` to your specific `"dotnet-react-db"` key:

```c#
builder.Services.AddDbContext<YourDbContext>(options =>
    options.UseSqlServer(builder.Configuration.GetConnectionString("dotnet-react-db")));
```

#### **Step C: Secure Your Files (`.gitignore`)**

Because this file contains live administrative passwords to your Azure SQL database, it must **never** be committed to Git.

**CRITICAL:** Open your `.gitignore` file and ensure this line is included:

```bash
**/*.secrets.json
```

#### **Step D: Run EF Core Migrations Against Azure SQL**

Because your cloud-hosted Azure SQL database is fresh and lacks the required schema tables (like your `Todos` table), you must execute your EF migrations to provision the database structure:

1. Open your terminal and navigate to your project directory.
2. Run the update command pointing explicitly to your project:

```bash
dotnet ef database update --project CapstoneApp.Host
```

_(This commands Entity Framework to read your local secrets file, connect directly to your Azure SQL database, and automatically build all required tables)._

#### **Step E: Test the Connection From Your Locally Run App**

Now that your database schema exists and your local secrets are wired up, you can test communication with your cloud-hosted database:

1. Run your application locally (e.g., using `dotnet run` or hitting F5 in Visual Studio).
2. Add a test todo item through your frontend or API (e.g., posting a record to `/api/todos`).
3. Verify that the record successfully appears in your cloud-hosted database by querying your tables in SQL Server Management Studio (SSMS) or checking your Azure SQL Database metrics in the Azure Portal.
