 
# Reference Guide: GitHub Actions CI/CD Pipeline & Secrets Setup

### 1. Architectural Purpose of GitHub Secrets & Service Principals

- **Zero-Credential Codebase:** Passwords, database connection strings, and login tokens are never hardcoded into your source files or committed to Git.
- **Service Principal Authentication:** Rather than logging in with a human user account, GitHub Actions authenticates using an Azure Service Principal (an application identity with strict permissions scoped directly to your resource group via role-based access control).

### 2. Step-by-Step Implementation Guide

#### **Step A: Generate Your Azure Service Principal (`AZURE_CREDENTIALS_DEV`)**

1. Log into the [Azure Portal](https://www.google.com/search?q=https://portal.azure.com/).
2. Click on the **Cloud Shell** icon ($\mathbf{>\_}$) in the top header bar and select **Bash**.    
3. Run the following command to create your service principal, scoping it directly to your development resource group and assigning the `Contributor` role (make sure to replace `YOUR_SUBSCRIPTION_ID` with your actual Azure subscription ID):

```bash
az ad sp create-for-rbac --name "capstone-github-actions-dev-sp" --role Contributor --scopes /subscriptions/YOUR_SUBSCRIPTION_ID --json-auth
```

1. **Copy the JSON Output:** Save the entire JSON block returned by the terminal securely—you will need it for the next step.

#### **Step B: Store Your Credentials in GitHub Secrets**

1. Navigate to your GitHub repository in your browser.
2. Click on the **Settings** tab at the top.
3. In the left sidebar, expand **Secrets and variables** and click **Actions**.
4. Click **New repository secret** and add your environment-scoped secrets:
      
    - **Secret 1:**
        - **Name:** `AZURE_CREDENTIALS_DEV`
        - **Secret:** Paste the entire JSON service principal block you generated in Step A.
		
    - **Secret 2:**
        - **Name:** `AZURE_SQL_CONNECTION_STRING_DEV`
        - **Secret:** Paste your Azure SQL Database ADO.NET connection string (with your real database password included).

    - **Secret 3** (see next step for this):
		    - **Name:** ACR_PASSWORD
		    - **Secret:** Paste the admin password from your Azure Container Registry (`dotnetreactacr`) **Access keys** menu (after enabling the Admin user).

#### **Step C: Enable Admin User on Azure Container Registry (ACR)**

To allow your Container App to securely pull private container images from your registry:

1. Open your Azure Container Registry (`dotnetreactacr`) in the Azure Portal.
2. Under **Settings** on the left menu, click **Access keys**.
3. Toggle **Admin user** to **Enabled** (note down the generated password for your `ACR_PASSWORD` GitHub secret).

#### **Step D: Create the GitHub Actions Workflow File (`deploy-dev.yml`)**

1. In your local repository, create the directory path if it doesn't already exist: `.github/workflows/`.
2. Inside that folder, create a new file named **`deploy-dev.yml`**.
3. Paste the pipeline configuration below. This workflow is set to trigger on **any push** across all branches so that your feature and main branches automatically build and deploy to your dev server, check out your code, dynamically write your ignored `appsettings.secrets.json` file using your GitHub secret, build your Docker image, push it to Azure Container Registry (ACR), and update your Azure Container App:    

```yaml
name: Deploy Dev Environment

on:
  # Runs on all pushes to repository
  push:

jobs:
  build-and-deploy:
    runs-on: ubuntu-latest
    steps:
      - name: Checkout repository
        uses: actions/checkout@v4

      - name: Azure Login
        uses: azure/login@v2
        with:
          creds: ${{ secrets.AZURE_CREDENTIALS_DEV }}

      # Dynamically creates appsettings.secrets.json file on the fly for the build
      - name: Create appsettings.secrets File
        run: |
          echo "{
            \"connectionstrings\": {
              \"_msg\": \"add any necessary connection string names here, put the strings themselves in appsettings.secrets.json\",
              \"dotnet-react-db\": \"${{ secrets.AZURE_SQL_CONNECTION_STRING_DEV }}\",
              \"dotnet-react-db.dev\": \"${{ secrets.AZURE_SQL_CONNECTION_STRING_DEV }}\"
            }
          }" > CapstoneApp.Host/appsettings.secrets.json

      - name: Log in to ACR via Azure CLI
        run: |
          az acr login --name dotnetreactacr

      - name: Build and push Docker image
        uses: docker/build-push-action@v5
        with:
          context: .
          file: ./Dockerfile
          push: true
          tags: dotnetreactacr.azurecr.io/dotnet-react-app:${{ github.sha }}

      - name: Deploy to Azure Container App
        uses: azure/container-apps-deploy-action@v2
        with:
          containerAppName: dotnet-react-dev
          resourceGroup: rg-dotnet-react-dev
          imageToDeploy: dotnetreactacr.azurecr.io/dotnet-react-app:${{ github.sha }}
          acrName: dotnetreactacr
          acrUsername: dotnetreactacr
          acrPassword: ${{ secrets.ACR_PASSWORD }}
```

#### **Step E: Commit, Push, and Verify Your Pipeline**

1. Stage, commit, and push your new workflow file to GitHub:

```bash
    git add .github/workflows/deploy-dev.yml
    git commit -m "Add GitHub Actions workflow for global dev deployment"
    git push origin main
```

2. Head over to the **Actions** tab in your GitHub repository to watch your pipeline run live!
3. Once the workflow turns green, navigate to your Azure Container App URL to verify that your application has been successfully deployed to the cloud.
