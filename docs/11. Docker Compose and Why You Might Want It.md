Yes, **this exact scenario is precisely why `docker-compose.yml` exists and why developers use it!** ### Why `docker-compose` Solves This

If you had used a `docker-compose.yml` file, it would have spun up _two_ containers simultaneously on an internal Docker network:

Because they would be on the same internal network, your app container would be able to talk to the SQL Server container, meaning your database migrations would run, and hitting `http://localhost:8080` would let you view _and_ successfully create/save todos right inside the containerized environment!
