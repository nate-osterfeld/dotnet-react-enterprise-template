# Reference Guide: Azure Infrastructure Setup (Clean Architecture + Quickstart Workaround)

### 1. Finalized Resource Structure

- **`rg-capstone-shared` (Global Core):**
    - **Azure Container Registry (`dotnetreactacr`)**: Stores all container images centrally for Dev, Test, and Prod.
- **`rg-capstone-dev` (Isolated Dev Environment):**
    - **Container Apps Environment (`cae-capstone-dev`)**: Shared serverless compute cluster running in **East US 2**.
    - **Container App (`dotnet-react-dev`)**: The Dev web service instance.

### 2. Step-by-Step Portal Setup Walkthrough

#### **Step A: Create the Shared Core (Registry)**

1. Create Resource Group `rg-capstone-shared` in **East US 2**.
2. Create Container Registry `dotnetreactacr` inside `rg-capstone-shared` (Basic SKU, RBAC permissions).

#### **Step B: Create the Dev Environment & Container App**

1. Create Resource Group `rg-capstone-dev` in **East US 2**.
2. Create Container App `dotnet-react-dev` inside `rg-capstone-dev`:
    - **Environment:** Create new named `cae-capstone-dev` in **East US 2**.
    - **Container Image Section (The Quickstart Workaround):** * Check **"Use quickstart image"** on initial creation. _(Why? This bypasses the empty registry error since your code hasn't pushed yet, and provisions the container successfully using a default NGINX image)._
    - **Ingress Tab:** Enable Ingress, set to **"Accepting traffic from anywhere"** (External).

_Note: Once your GitHub Actions pipeline runs for the first time, it will automatically build your custom C#/React app, push it to `dotnetreactacr`, and overwrite the quickstart image with your real application code while updating your target port to `8080`._
