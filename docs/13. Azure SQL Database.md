# Reference Guide: Provisioning Azure SQL Database (Dev Tier)

### 1. Architectural Purpose

* **Dedicated Cloud Database:** While local development uses `(localdb)\mssqllocaldb` via SSMS, your Dev environment in Azure requires a managed cloud database (`Azure SQL`) so that your deployed container app can save and fetch real data in the cloud.
* **Security & Configuration:** Database credentials and connection strings are never hardcoded into source code or Dockerfiles. Instead, they are generated securely in Azure and injected at runtime via environment variables (or GitHub Secrets).

---

### 2. Step-by-Step Portal Setup Walkthrough

#### **Step A: Create the Azure SQL Logical Server**

1. In the Azure Portal, search for **SQL servers** (or Azure SQL) and click **+ Create**.
2. **Resource Group:** Select `rg-capstone-shared` (or your dev group).
3. **Server Name:** Give it a unique lowercase name (e.g., `capstone-sql-server-dev`).
4. **Location:** `East US 2` (matching your container infrastructure).
5. **Server Admin Login:** Choose an admin username (e.g., `sqladmin`).
6. **Password:** Set a strong administrator password and save it securely.
7. Click **Review + create** -> **Create**.

#### NOTE: If a database is automatically created after deploying Azure SQL Server, you can skip steps "B" and "C" and simply use it instead.

#### **Step B: Create the Database**

1. Once the logical server finishes provisioning, go to its overview page and click **+ Create database**.
2. **Database Name:** `CapstoneDb`
3. **Compute + storage:** Click *Configure database*. For a dev or capstone tier, choose the **Serverless** compute tier (or a low-cost Basic/Standard DTU model) to save student credits and automatically pause when not in use.
4. Click **Review + create** -> **Create**.

#### **Step C: Configure Firewall & Allow Azure Services**

1. Go to your SQL Server resource in the Azure Portal.
2. On the left menu, click **Networking** (or Firewalls and virtual networks).
3. Look for the setting: **"Allow Azure services and resources to access this server"** and toggle it to **Yes** *(This is crucial so your Azure Container App can talk to the database securely).*
4. Click **Save**.

#### **Step D: Retrieve and Save the Connection String**

1. Navigate to your newly created `CapstoneDb` database in the portal.
2. Click on **Connection strings** on the left menu.
3. Copy the **ADO.NET** connection string tab. It will look like this:
```text
Server=tcp:capstone-sql-server-dev.database.windows.net,1433;Initial Catalog=CapstoneDb;Persist Security Info=False;User ID=sqladmin;Password={your_password};MultipleActiveResultSets=False;Encrypt=True;TrustServerCertificate=False;Connection Timeout=30;

```

4. Replace `{your_password}` with the actual password you created.
5. Save this connection string safely—we will add it to your GitHub Repository Secrets next so your CI/CD pipeline can inject it into your Dev Container App!
