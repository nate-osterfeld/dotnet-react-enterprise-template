> Note: We will not be using docker-compose as it is unnecessary for our purposes. This means, however, that our local persistence (mssqllocaldb) will not be accessible from inside the container. Once it is hosted to the cloud this will change as the environment variables will be injected into the app and accessible on a public network. If we added docker-compose we could create an instance of SQL Server inside its own container with a local network to bridge them, but again this is not necessary for our app to run.

Testing your `Dockerfile` locally before writing your GitHub Actions pipeline is a **fantastic learning step**. It bridges the gap between running your app natively in Visual Studio and seeing it packaged inside an isolated Linux container, exactly how it will run in Azure.
### Do you _need_ to use it yet?

Strictly speaking, no—your app is already working locally via Visual Studio and LocalDB. However, building and running the container locally ensures that your multi-stage `Dockerfile` (which builds the React frontend and compiles the .NET monorepo) has zero syntax or path errors _before_ you hand it over to GitHub Actions.
### How to Test Your Dockerfile Locally

You can build and run your container using standard Docker CLI commands right from your root solution directory (`CapstoneApp`).
#### 1. Build the Docker Image

Run this command in your terminal from the root folder where your `Dockerfile` lives:
- **`docker build -t capstone-app .`**
    - _What it does:_ Tells Docker to execute your 3-stage build process. It builds the React frontend in Node, compiles your C# projects in the .NET SDK, and packages everything into a final lightweight runtime image tagged as `capstone-app`.

#### 2. Run the Container Locally

Once the build completes successfully, you can spin up a container instance from that image:

- **`docker run -d -p 8080:8080 --name my-running-app capstone-app`**      
    - _What it does:_ Starts your container in detached mode (`-d`), maps port `8080` on your host machine to port `8080` inside the container, and gives it a friendly name.

#### 3. Test It in Your Browser

Open your browser and navigate to:

- **`http://localhost:8080`**
    - You should see your React frontend load successfully, served directly out of the C# backend running inside the Linux container!
    - _(Note: Because this container is running in isolation without a local SQL Server instance inside it, calls to fetch/save todos might fail until it points to a database, but verifying that the frontend and backend boot up and serve via port `8080` proves your `Dockerfile` is working perfectly)._

#### 4. Clean Up When Done

When you're finished testing, you can stop and remove the container:

```bash
docker stop my-running-app
docker rm my-running-app
```
